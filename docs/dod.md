# 出費会議 完了の定義（DoD）

ここに書いた条件をすべて満たしたときに、出費会議を完成とします。

## 完了条件チェックリスト

確認方法: `npm run test:all`（`test/logic.test.js` 22件 + `test/ui.test.js` 11件、すべて合格）。

- [x] 機能要件 FR-1〜FR-11 の受け入れ基準をすべて満たす
- [x] テストシナリオ T-1〜T-11 がすべて合格する
- [x] 16件で質問が最大49問以内に収まる（乱数50通りで38〜49問）
- [x] 16件の結果計算が1秒未満で終わる（数ミリ秒）
- [x] スマホ幅（約400px）で横スクロールが出ない（register / compare / result の3画面、ライト・ダーク）
- [x] ライトとダークの両方で文字が読める（スクリーンショットを目視で確認。コントラスト比の機械計測はしていない）
- [x] 再読み込みしても、予算・アイテム・順位・回答途中の状態が戻る
- [x] 買った・やめる・削除・復活のあとで、予算と結果が正しい値になる
- [x] PRD と ER図の内容と、実装が一致している

## 機能ごとの受け入れ基準

| 要件 | 確認方法 | 合格ライン |
| --- | --- | --- |
| FR-1 | 予算に 5.000.000 と入力し、ページを再読み込みする | 「Rp 5.000.000」と表示され、再読み込み後も残る |
| FR-2 | 名前なし、または値段 0 で追加する。17件目を追加する | どちらもエラーが出て追加されない |
| FR-3 | 16件で質問に最後まで答える | 質問数が38〜49問。順位表が16件そろう |
| FR-4 | 「ひとつ戻る」「どちらでもいい」を押す | 戻ると直前の質問と順位表になる。どちらでもいいは新しい方が下に入る |
| FR-5 | 3〜5件の小さな入力で、結果を手計算と比べる | 買い物の合計が予算以下で、合計点が最大である |
| FR-6 | 「買った」を押す | 残り予算が値段の分だけ減り、購入済みに移る |
| FR-7 | 「購入を取り消す」を押す | 予算が値段の分だけ戻り、候補に戻る |
| FR-8 | 「やめる」を押して比較を続け、後から「復活」を押す | やめた間は質問に出ない。復活後は元の順位に戻る |
| FR-9 | 「削除」を2回押す | 一覧・順位表・回答履歴のすべてから消える |
| FR-10 | 完了後にアイテムを追加する | 追加分の質問だけが出て（最大4問）、順位に入る |
| FR-11 | ページを再読み込みする | 直前の状態が復元される |

## テストシナリオ

| ID | 手順 | 期待結果 |
| --- | --- | --- |
| T-1 | 初回に開く。アイテムを1件追加する | サンプルが表示され、追加するとサンプルが消える |
| T-2 | 予算より高いアイテムを登録する | 「予算超え」と出て、質問に出ない |
| T-3 | 16件を登録して、質問に最後まで答える | 質問が49問以内で終わり、結果が出る |
| T-4 | 「どちらでもいい」を押す | 新しいアイテムが相手の下に入る |
| T-5 | 「ひとつ戻る」を3回押す | 質問と順位表が3問前に戻る |
| T-6 | 結果で「買った」を押す | 残り予算が値段の分だけ減り、結果が計算し直される |
| T-7 | 購入済みの「購入を取り消す」を押す | 予算が戻り、候補に戻る |
| T-8 | 「やめる」を押し、質問を続けてから「復活」する | やめた間は質問に出ない。復活すると元の順位に戻る |
| T-9 | 「削除」を1回押し、さらにもう1回押す | 1回目は確認表示、2回目で消える。順位と履歴にも残らない |
| T-10 | 完了後に新しいアイテムを追加する | 追加分の質問だけが出て、順位に入る |
| T-11 | ページを再読み込みする | 予算・アイテム・順位・回答途中の状態が戻る |

## 品質基準

| 項目 | 基準 |
| --- | --- |
| 質問数 | 8件で最大17問、16件で最大49問 |
| 計算時間 | 16件の結果計算が1秒未満 |
| 表示幅 | 約400pxで横スクロールが出ない |
| テーマ | ライトとダークの両方で、文字と背景のコントラストが十分 |
| 保存 | 変更のたびに保存する。localStorage が使えない環境でも、エラーなく動く（保存されないだけ） |
| ボタン | タップするボタンの高さは36px以上 |
